# Notifications

The Single Solution product that sends WhatsApp, e-mail, SMS, browser push, staff push and outgoing webhooks for any
product and for the merchant's own server, through the merchant's own provider keys (PLAN.md 0.8.5, step 6). Built on
`@ss/app-kit`; generated by `ss app init` and built out.

## Features

| Key              | What it does                                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| `whatsapp`       | WhatsApp through Meta WhatsApp Cloud API, Twilio, or any gateway over HTTP (Connectivity.pk, local gateways)      |
| `email`          | E-mail through SMTP, Resend, SendGrid, Mailgun or Amazon SES                                                      |
| `sms`            | SMS through Twilio or any gateway over HTTP                                                                       |
| `browser_push`   | Web push to visitors (the push-permission widget), with the merchant's VAPID keys                                 |
| `staff_push`     | Web push to the merchant's staff (admin widget with a ticket)                                                     |
| `webhooks`       | Signed events (`message.sent`, `message.failed`, `recipient.unsubscribed`) to up to 5 URLs, retried on later uses |
| `fallback`       | After the retries, one more try on the fallback channel set per channel (e.g. WhatsApp → SMS)                     |
| `quiet_hours`    | Non-urgent messages wait for the end of the quiet window in the recipient's time zone                             |
| `send_limits`    | Messages per recipient per hour and per day                                                                       |
| `delayed_send`   | `sendAt`: sent on the first use of the website after that time                                                    |
| `multi_language` | Template versions per language (exact code, then base language, else the default version)                         |
| `send_api`       | The merchant's own template keys, the delivery log routes and the admin widgets                                   |

There is no background work: a message due now is attempted inside the request that sends it; retries (3 per channel,
after 1 and 5 minutes), quiet-hour and delayed messages and webhook retries are sent right after the next requests for
that website. The delivery log (every attempt) is kept forever in the merchant's database.

## Layout (PLAN 0.4.13)

| Folder      | What it holds                                                                                                                      |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `core/`     | pure logic: channels and recipients, templates, timing (retries, quiet hours, limits), gateway answers, replies, snippets          |
| `api/`      | routes, sending (`sending.js`), the hosted unsubscribe page, the public docs, the generated widget bundle                          |
| `adapters/` | the kit wiring (`product.js`), providers, SMTP (moved here from the kit), web push, signatures, the merchant database (`store.js`) |
| `ui/`       | widgets: `push_permission` (visitor), `staff_push_permission`, `delivery_log`, `template_editor`, `send_message` (admin)           |
| `app/`      | Next.js: the API function and the dashboard (Overview · Features · Settings with Templates · Connections · Developers)             |
| `strings/`  | every word of the widgets and the unsubscribe page (Settings → Texts)                                                              |
| `schemas/`  | each feature's settings schema                                                                                                     |
| `tests/`    | Vitest on the kit's fake Portal with fake providers (no real network call), MongoDB and jsdom                                      |
| `docs/`     | the public docs' texts, served at `/docs`                                                                                          |

## The send API

`POST /v1/messages/{email,sms,whatsapp,push,staff-push}` with the server token (other products use the Notifications
token pasted into their Connections): `{ template, to: { email?, phone?, subscriberId?, staffId?, language?, timeZone? },
values?, language?, sendAt? }` → 201 with the message (`sent`, `queued`, `retrying`, `failed` or `skipped`). Template
keys starting `accounts.`, `ecommerce.`, `chat.`, `payments.` or `growth.` are the other products' events; any other key
needs `send_api`. The full reference is at `/docs`.

## Environment and deploying

Exactly three variables (`.env.example`): `MONGODB_URI` (this product's own database), `CONNECT_SECRET` and
`ENCRYPTION_KEY` (each random, at least 32 characters). Deploy with the Vercel project root `products/notifications`,
set the three variables for Production, then connect it in the Portal: Products → Add product, with its address and
`CONNECT_SECRET`, then set it Active.

## Scripts

`pnpm dev` / `pnpm build` (both regenerate `openapi.json` and `api/widget-script.js` first) / `pnpm start`,
`pnpm check` (format, lint, typecheck, tests with coverage) and `pnpm validate` (`ss app validate`).
