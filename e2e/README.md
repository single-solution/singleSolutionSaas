# @ss/e2e — system tests

Tests that need two or more deployables: products against the **real** Portal, in process, on one MongoMemoryReplSet.
They use only public entry points (`@ss/platform/testing`, `@ss/app-kit`, `@ss/app-kit/testing`, `@ss/protocol`, the
shipped products' `./product` and `./routes`, e.g. `@ss/product-notifications`) and the test product below, never
another unit's internals. This workspace is private and is never deployed; it has no
source of its own to measure, so coverage is measured by each unit's own run, not here.

## The test product (`fixtures/notes`)

A minimal product generated by `ss app init fixtures/notes --id notes --name Notes --base-url https://notes.test`
(PLAN 0.12 step 5; test-only, never deployed, not a workspace package, not in CI's unit list). It is kept as generated
except for what a test fixture does not need: the Next.js files (`app/`, `next.config.js`, `postcss.config.mjs`),
`vercel.json`, its own tests and unit configs (`package.json`, `eslint.config.js`, `tsconfig.json`,
`vitest.config.js`), its README and the generated `.env.local` (never committed). What remains (`core/`, `api/`,
`adapters/`, `ui/`, `schemas/`, `strings/`, `docs/`, `manifest.json`, `openapi.json`) is part of this unit: it is
linted and type-checked with this folder's config, and the tests compose it by relative path
(`fixtures/notes/adapters/product.js` → `createProductInstance`, `fixtures/notes/api/routes.js` → `createRoutes`).

## How the tests run

`tests/helpers.js` (`startSystem({ unit })`, Notes unless a shipped product's `unit` is given) starts, per test file, the Portal (`createPortal` with the real `system`,
`catalog`, `identity` and `commerce` modules) and Notes on the real kit, each on its own database of the shared replica
set (the merchant databases too), wired through one in-process fetch router (`createNetwork`): the Portal's connect
calls and notices reach the product's handler, and the product's reports, status, revocation, websites and launch calls
reach the Portal's handler. One clock drives both and moves one second after every call (identical notices are never
signed in the same second); work after responses is run before each call returns. People are created the way PLAN 0.2
says (first admin, invites, merchant setup links from an in-memory mailer). `setReachable(false)` makes the product
answer 503, for notices that must wait.

| File                          | Covers                                                                                                                                                                                                                                                                                         |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/connect.test.js`       | Add product (URL + connect secret, wrong secret 401): inactive, price list 1 all 0; an id already connected refused (use Reconnect); Set active offers it; Reconnect keeps id, websites, tokens and switches                                                                                   |
| `tests/tokens.test.js`        | Add product issues both tokens; Install and tokens (browser token, script and docs URLs); Finance 403; reveal not cached; browser token origins (exact https domain and local only); server token without Origin; other product's tokens 401; regenerate → old token 401 after `token.revoked` |
| `tests/reports.test.js`       | Prices screen (Owner launch) → price report accepted (Support 403, negative refused); Features save (Support) → feature report, Activity, charging (`todayMillicredits` after an hour); a refused feature report changes nothing in the product                                                |
| `tests/statuses.test.js`      | active, grace (credits run out), stopped (grace days pass), credits restart at once, suspended (API 403 `suspended`, merchant cannot launch, admin can), removed (403 `removed`; re-add restores the same tokens with every feature off)                                                       |
| `tests/tickets.test.js`       | tickets from the server token, bound to one origin, 15 minutes; refused while stopped or suspended; regenerating the server token ends them                                                                                                                                                    |
| `tests/dashboard.test.js`     | merchant launch (its websites only), single use and 60 s, admin launches (Owner Defaults, Support, Finance refused), `sessions.revoked` on password change, sign-out, role change and suspension                                                                                               |
| `tests/contract.test.js`      | websites list and admin switcher (removed excluded, suspended listed), status for removed and never-added websites, revocations with cursors, directory, a notice kept while the product is down and delivered after its next Portal call                                                      |
| `tests/notifications.test.js` | Notifications (step 6): connect (12 features, price list 1 all 0), price and feature reports, a send through the send API with the Portal-issued server token and an in-process fake e-mail provider, the delivery log through a ticket, a feature that is off refused, the hourly charge      |
| `tests/websites.test.js`      | data-rights export and delete with the server token; Remove website refused while products remain, then the domain is free, tokens revoked and the product deletes its product-database rows (`website.deleted`), not the merchant database                                                    |

The tests of the old products are kept for reference in `parked/e2e/` with the parked product folders (PLAN 0.12 step
4); they are not run. `products/chatbot` has no system test until it is rebuilt as Chat (step 8).
